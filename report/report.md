# AppleSupport grounded-support triage report

## Framing and data

This system triages an incoming AppleSupport tweet into one of ten actionable intents, retrieves historical AppleSupport resolutions, and returns a grounded historical reply or escalates. AppleSupport was selected after brand analysis because the indexed TWCS data has about 80,717 conversations and a high share of simple customer→brand exchanges. The source is historical public Twitter data, not a current support-policy corpus.

## Method

The source is an SQLite index and a 51 MB Apple conversation JSONL. Retrieval extracts first customer message → first brand response pairs, stores conversation/tweet provenance, and excludes all evaluation conversation IDs. Baseline 1 is majority intent + generic reply + always escalate. Baseline 2 uses word/bi-gram TF-IDF logistic classification, nearest TF-IDF historical response, and always auto-handles. The final system retains the same reproducible offline classifier/retriever but escalates account/payment issues, intent confidence below 0.38, or top-1 evidence similarity below 0.12. It returns the actual historical response, not an invented policy.

## Evaluation status and executed result

`scripts/run_evaluation.py` ran successfully on 609 training and 191 held-out conversations. It writes full per-intent reports, routing metrics, prediction/evidence JSONL, and a confusion matrix under `results/`. The labels were generated by deterministic keyword heuristics, so the result status is `PROVISIONAL_SILVER_ONLY_NOT_A_GOLDEN_EVALUATION`.

## Golden-set protocol

The repository supplies a stratified 200-row review template from the 800-message discovery sample, an intent/routing guide, and an evaluation command that automatically prefers `data/labels/golden_labels.csv` after an independent human completes it. The template is deliberately blank and marked `human_pending`; it is not falsely called hand-labelled. Golden conversations are removed from both training and the retrieval corpus.

## Failure modes

The five data-backed provisional examples and remediation hypotheses are in [failure_analysis.md](failure_analysis.md): noisy/multi-intent tweets, taxonomy boundaries, rare hardware, content-loss ambiguity, and over-conservative confidence routing.

## What is misleading about my headline number?

The current number measures agreement with silver labels that were created from rules related to the model’s input features; it cannot establish real accuracy. Even after human review, 200 examples gives broad uncertainty for rare intents. Tweets are brief/noisy, the corpus reflects 2017-era support behavior and possibly obsolete policies, and neither retrieval similarity nor an LLM judge proves factual correctness. Historical replies lack private account/device context. A low false-auto rate can also be obtained by escalating nearly everything, as this conservative run demonstrates.

## Deliberately not built

There is no frontend, authentication, social-media integration, deployment setup, fine-tuning pipeline, or multi-agent workflow. Those do not improve the evidence needed for this assignment under the time constraint.
